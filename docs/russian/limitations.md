# Ограничения

Что envgraph умеет сегодня, чего не умеет и что планируется.

## Реализовано

- CLI с командами: `scan`, `check`, `create example`, `create config`, `help`,
  `version` и проверочной командой по умолчанию.
- Конфигурация проекта через `envgraph.config.{ts,mts,js,mjs,cjs,json}`:
  автоматическое обнаружение (побеждает ближайший), поиск вверх до корня
  проекта; сломанный конфиг даёт предупреждение и откат к значениям по
  умолчанию.
- AST-детекция `process.env.NAME` и `process.env["NAME"]` в
  `.js`/`.jsx`/`.ts`/`.tsx`.
- Детекция загрузки окружения: `import "dotenv/config"`, `dotenv.config()`,
  `require("dotenv").config()`, нативный `process.loadEnvFile()`.
- Обнаружение файлов `.env*` по имени (содержимое никогда не читается).
- Сгруппированный отсортированный отчёт с точными строками; ошибки разбора —
  в stderr.
- Генерация `.env.example` из `.env`: очистка секретов по имени, сохранение
  порядка, `--force`, `--dry-run`, TTY-подтверждение перезаписи. Настройка
  через конфиг: `example.keepComments` и `example.defaults` (полная замена).
- Серая подсказка в stderr при запуске `scan` из подпапки проекта.

## Не поддерживается сегодня

- Псевдонимы, деструктуризация, динамические обращения (`e.PORT`,
  `const { PORT } = process.env`, `process.env[name]`).
- Другие глобальные объекты вроде `import.meta.env`.
- Только места использования — значения не показываются, связь переменной с
  конкретным файлом `.env` не строится.
- Лоадеры ограничены npm-пакетом `dotenv` и нативным API Node.js.
- В `.env`: нет интерполяции, многострочных значений, `export KEY=value`.
- Санитайзер работает только по именам.
- Только `.env` → `.env.example`; другие форматы файлов не поддерживаются.

## Пока не работает / планы

- **`include` / `exclude` / `outputFormat` в конфиге** теперь применяются:
  глоббы фильтруют сканируемые файлы, а `outputFormat` задаёт формат
  вывода `scan` по умолчанию (`classic`; явный флаг `--format` главнее).
- **Программный API анализа** — `analyzeProject` и `runEnvGraph` возвращают
  пустой результат; рабочая реализация — `scanProject` в
  `src/core/scanner/`.
- **Номера столбцов** — заявлены в типах, но сканером не выдаются.

Режима watch и системы плагинов сейчас нет.
