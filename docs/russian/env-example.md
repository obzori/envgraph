# Генерация .env.example

Как `envgraph create example` превращает ваш `.env` в `.env.example`.

## Использование

```bash
envgraph create example [--force] [--dry-run]
# короткие формы: -f (force), -d (dry-run)
```

И `.env`, и создаваемый `.env.example` находятся в текущей рабочей
директории.

## Переопределения из конфига

Генерацию можно настроить через `example`-секцию файла
`envgraph.config.{js,mjs,cjs,ts,mts,json}`:

```js
export default {
  example: {
    // сохранять комментарии из .env (по умолчанию: true)
    keepComments: false,
    // записать эти значения вместо значений из .env;
    // полная замена — важнее санитайзера чувствительных имён
    defaults: {
      DISCORD_TOKEN: "enter_here_your_discord_token",
      NODE_ENV: "development",
    },
  },
};
```

Приоритет для каждого присваивания:

1. ключ есть в `defaults` → значение из `defaults`;
2. иначе имя похоже на секрет → пустое значение;
3. иначе исходное значение из `.env`.

## Как разбирается .env

Файл разбирается построчно, по порядку:

- **Пустые строки** сохраняются.
- **Комментарии**, начинающиеся с `#` или `;`, сохраняются дословно.
- **Присваивания** `KEY=value`: разбиение по *первому* `=`, поэтому значения
  могут содержать `=`. Пустые значения (`KEY=`) поддерживаются. Кавычки
  остаются частью значения.
- **Произвольные строки** без `=` сохраняются как есть.

Порядок полностью сохраняется; вывод всегда заканчивается одним переводом
строки.

Не поддерживается: интерполяция переменных (`PATH=${OTHER}/bin` остаётся
литеральным текстом), многострочные значения и `export KEY=value`.

## Поведение перезаписи

- Если `.env.example` не существует — записывается напрямую.
- Если существует:
  - **интерактивный терминал**: запрос подтверждения; только `y`/`Y`
    перезаписывает;
  - **неинтерактивный режим (CI)**: отказ с выходом `1`.
- `--force` (`-f`) перезаписывает без вопросов.

Создать сам файл конфигурации можно командой `envgraph create config`.
