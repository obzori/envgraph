# Сканирование

Как `envgraph scan` находит файлы и анализирует использование переменных
окружения.

envgraph разделяет два понятия:

- **Использование переменной** — например, `process.env.PORT`.
- **Загрузка окружения** — например, `dotenv.config()` или
  `process.loadEnvFile(".env")`.

Оба фиксируются с точными местами. Значения из `.env` никогда не читаются и
не печатаются — только имена, пути и номера строк.

## Поиск файлов

- Рекурсивный обход текущей рабочей директории.
- Только расширения: `.js`, `.jsx`, `.ts`, `.tsx`.
- Полностью пропускаются каталоги: `node_modules`, `.git`, `dist`, `build`.
- Нечитаемые каталоги молча пропускаются.
- Файлы обрабатываются в отсортированном порядке путей (с прямыми слэшами).
- Ключи конфигурации `include` и `exclude` принимают glob-паттерны (`*`, `**`,
  `?`, `{a,b}`) для сужения набора сканируемых файлов.

## Поддерживаемый синтаксис

Детекция основана на **AST** (TypeScript compiler API), а не на регулярных
выражениях, поэтому сообщается только о настоящих обращениях.

### Доступ к переменным окружения

| Форма | Пример | Рантайм |
| --- | --- | --- |
| Точечная нотация | `process.env.PORT` | Node.js |
| Скобочная нотация со строковым литералом | `process.env["PORT"]` | Node.js |
| Деструктуризация | `const { PORT } = process.env` | Node.js |
| Деструктуризация с переименованием | `const { PORT: port } = process.env` | Node.js |
| Точечная нотация | `import.meta.env.MODE` | Vite |
| Скобочная нотация со строковым литералом | `import.meta.env["MODE"]` | Vite |
| Деструктуризация | `const { MODE } = import.meta.env` | Vite |
| Точечная нотация | `Bun.env.PORT` | Bun |
| Скобочная нотация со строковым литералом | `Bun.env["PORT"]` | Bun |
| Деструктуризация | `const { PORT } = Bun.env` | Bun |
| `Deno.env.get("NAME")` со строковым литералом | `Deno.env.get("PORT")` | Deno |

Остаточные элементы (`...rest`) и вычисляемые/динамические ключи в
деструктуризации пропускаются — сообщается только о статически разрешимых
именах.

Не обнаруживается:

- Псевдонимы: `const e = process.env; e.PORT`.
- Динамический доступ: `process.env[name]`.
- `Deno.env.get(variable)`, если аргумент не строковый литерал.

## Детекция лоадеров окружения

Детекция основана на AST, поэтому строковые литералы (`"dotenv.config()"`)
и комментарии никогда не срабатывают. Локальные модули или переменные с
именем `dotenv`, затеняющие npm-пакет, корректно игнорируются.

Распознаваемые формы dotenv:

| Форма | Сообщаемый файл |
| --- | --- |
| `import "dotenv/config";` | — (по умолчанию) |
| `dotenv.config()` | — (по умолчанию) |
| `require("dotenv").config()` | — (по умолчанию) |
| `import dotenv from "dotenv";` + `dotenv.config();` | — (по умолчанию) |
| `import * as dotenv from "dotenv";` + `dotenv.config();` | — (по умолчанию) |
| `const dotenv = require("dotenv");` + `dotenv.config();` | — (по умолчанию) |
| `dotenv.config({ path: ".env.local" })` | `.env.local` |

Если `path` — не строковый литерал (например, `process.env.ENV_FILE`),
лоадер всё равно сообщается, но без целевого файла — значения не вычисляются.

Нативный API Node.js:

| Форма | Сообщаемый файл |
| --- | --- |
| `process.loadEnvFile()` | — (по умолчанию) |
| `process.loadEnvFile(".env")` / `(".env.local")` | литеральный путь |

Разрешение импорта намеренно простое: только спецификаторы `"dotenv"` и
`"dotenv/config"` считаются npm-пакетом. Локальный модуль
(`import dotenv from "./dotenv"`) никогда не сообщается, а локальный объект
или переменная с именем `dotenv` в том же файле затеняет пакет.

## Обнаружение файлов .env

Сообщаются файлы по соглашению имён: ровно `.env` или начинающиеся с `.env.`
(`.env.local`, `.env.production`, `.env.example`,
`.env.development.local`, …). Имена вроде `.environment`, `env.txt` или
`something.env.backup` не совпадают. Во время сканирования читаются только
имена файлов.

## Группировка и вывод

Все обращения к переменной группируются в одну запись; переменные сортируются
по имени. Пути относительные, строки с 1. Пример без лоадеров:

```text
4 usages · 2 variables

LOG_LEVEL  src/app.ts:4
PORT       src/app.ts:1 ×3
```

При наличии лоадеров или файлов `.env` добавляются счётчик лоадеров и блоки
«Environment loaders» и «.env files» (только когда непустые):

```text
1 usages · 1 variables
1 env loaders

PORT  src/config.ts:1

Environment loaders

dotenv  src/index.ts:1
dotenv  src/config.ts:4 → .env.local
node-load-env-file  src/boot.js:2 → .env

.env files

.env
.env.local
```

См. [Справочник CLI](cli.md) для полного описания формата вывода и кодов
выхода.

## Ошибки разбора

Если файл не читается или не разбирается, сканирование продолжается.
Ошибки печатаются в stderr после отчёта как
`envgraph scan: could not parse <file>: <message>`. Исходный текст в ошибках
не появляется. Код выхода остаётся `0`.

## Большие каталоги

Перед чтением исходников выполняется дешёвая проверка размера: подсчёт записей
останавливается после 50 000. Без `--force` скан **отклоняется** (выход `1`),
с `--force` печатается предупреждение и скан продолжается. Дополнительно,
если найдено больше 10 000 исходных файлов, печатается второе предупреждение.

## Примеры

```bash
envgraph scan                 # сканировать проект в текущей директории
envgraph scan --force         # сканировать даже очень большой каталог
envgraph scan --help          # справка по команде
```
